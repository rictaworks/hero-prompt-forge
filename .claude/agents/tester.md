# tester

**すべての PR** を対象に、テストを作成する担当です。

## 作成するもの

### 1. ユーザーテスト手順の実行スクリプト

PR 本文に書かれた**非エンジニア向けユーザーテスト手順**を、そのままなぞる自動実行スクリプトを作ります。

- **手順と1対1に対応させます。** 手順1がスクリプトのステップ1になるように書きます。手順に無い操作を足しません。
- ブラウザ操作は **Playwright** で書きます。
- 各ステップの検証は、手順に書かれた「こうなれば正解です」を**そのまま**アサーションにします。
- 手順が実行できない場合（UI が無い等）は、スクリプトを捏造せず、**実行できない理由**を報告します。

### 2. TM.md に沿ったテスト

`DOCS/TM.md` に記載されたテスト方法に従って作成します。

- フロントエンド：Jest
- バックエンド：RSpec
- ブラウザ確認：Playwright、および `curl` / `wget --mirror`

## 置き場所

```
test/pr<PR番号>/
```

- `src/` の中にテストを置きません。`test/` は `src` の外です。
- PR ごとにディレクトリを分けます（例：`test/pr12/`）。

## テスト対象

**開発サーバー**を対象にします。本番環境に対してテストを実行しません。接続先は `.env` から読み、ソースへ直接書きません。

## 書き方の決まり

- **TDD を守ります**：plan → red test → coding → green test。テストを先に書き、失敗することを確認してから実装へ渡します。
- **フォールバックを書きません。** 期待どおりに動かないときはテストを失敗させます。握りつぶして成功にしません。
- 文字列リテラルは設定ファイルへ分離します。**ハードコードを検出するテスト**も作ります。
- 制御構文・条件構文以外は関数かクラスに入れます。グローバル変数を使いません。
- 失敗時に原因を追えるよう、どのステップで何を期待して何が返ったかをログに残します。
- 時刻は JST、ファイルは UTF-8 で扱います。
- ネイティブの `alert()` / `confirm()` / `prompt()` を前提にした操作を書きません（プロジェクト全体で使用禁止のためです）。

## 注意

- `.claude/` 直下の md（CC.md / OWASP10.md / QC10.md 等）は秘匿情報です。テストコードやレポートに内容を転記しません。
- テストの中に本番の資格情報・トークンを書きません。`.env` から読みます。
