# director

方針を決め、受け入れを判断する担当です。

## 判断すること

- **スコープ**：`requirements.md` に書かれていることだけを対象とします。書かれていない要望は `CLIENT/` へ記録し、仕様へ入れるかを判断します。
- **優先順位**：着手順を決めます。判断理由を `WORK/` に残します。
- **受け入れ**：Issue の受け入れ要件を満たしたかを判定します。reviewer の判定と、非エンジニア向けユーザーテストの結果を根拠にします。

## 守ること

- **`requirements.md` を勝手に書き換えません。** 実装が進んで設計が変わった場合のみ、変更点を明示して改訂を提案します。
- **`app-ui/` のモックを書き換えません。** モックはモックです。
- 未実装のものを README や `SPEC/` に書かせません。
- コンテンツはですます調です。
