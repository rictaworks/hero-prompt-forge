# リリース規程

公開の前に、この文書の条件をすべて満たしていることを確認します。**規程が不在の場合、監査は「判定不能」を返し、合格に届きません。**

## バージョン番号

形式は **メジャー2桁.マイナー2桁.デバッグ2桁** です。初期値は `01.01.00` です。

| 桁 | 上げる条件 |
|---|---|
| メジャー（先頭2桁） | 利用者の操作手順が変わる変更、互換性を失う変更、提供範囲が変わる変更を含む場合に上げます。下位2組は `00` に戻します |
| マイナー（中央2桁） | 機能の追加、画面の追加、外部との接点の追加を含む場合に上げます。末尾2桁は `00` に戻します |
| デバッグ（末尾2桁） | 不具合の修正、文言の修正、内部の整理のみの場合に上げます |

`01.09.00` の次のマイナーは `01.10.00` です。桁あふれはしません。

## 規則辞書の版

規則辞書（`config/rule_dictionary/initial.yml` と管理画面から編集する内容）は、
アプリケーションのバージョンとは別に版を持ちます。

- **内容を変えたら、必ず版を上げます。** 公開済みの版は書き換えません。
- 版を据え置くと、すでに古い版を投入した環境へ新しい内容が届きません。
  初期データの手順は、その版が無いときだけ書き込むためです。
- 版は生成履歴へ記録します。どの版で作った案かを、あとから追えるようにします。

## タグ

- **注釈付きタグを必須とします。** 作成は `git tag -a <バージョン> -m "<説明>"` です。軽量タグを使いません。
- タグ名はバージョン番号そのものです（接頭辞を付けません）。
- タグは KDP 等の外部提出物と1対1で対応させません。本リポジトリでは公開したリリースと1対1で対応させます。

```bash
git tag -a 01.01.00 -m "初回リリースです。"
git push origin 01.01.00
```

## 必須添付物

リリースノートに以下をすべて記載します。1つでも欠けた場合、配置を行いません。

| 添付物 | 内容 |
|---|---|
| 変更点の一覧 | 含まれる PR 番号と、利用者から見た変更内容 |
| 検証の記録 | `review-records/` のうち、本リリースに含まれる範囲 |
| 監査の結果 | release-audit の判定と報告書の所在 |
| セキュリティゲートの結果 | release-security-gate の判定 |
| ユーザーテストの結果 | 対象 PR の非エンジニア向け手順の実施結果 |

## 検証・承認の記録

**版管理の対象として残します。** `review-records/` に、セキュリティレビュー・コードレビュー・PR 整備の記録を置きます。リリース時点で、含まれるすべての PR について3種類の記録がそろっていることを確認します。

## 配置の起点

**GitHub Releases の発行が起点です。** `main` へのマージだけでは本番は動きません。

監査（release-audit）とセキュリティゲート（release-security-gate）は、Releases の発行を合図に **Claude Desktop 側で実施**します。CI 側では実施しません。

## 配置の順序

1. 必須添付物の確認（欠けていれば以降を実行しません）
2. バックエンド（Railway）
3. フロントエンド（Vercel）
4. 本番の応答確認

## 確認先の指定

確認先の URL は **Variables** に置きます。Secrets には置きません。ワークフローへ直接書きません。

| 名前 | 種別 | 用途 |
|---|---|---|
| `FRONTEND_BASE_URL` | Variables | 公開しているフロントエンドの URL |
| `BACKEND_HEALTH_URL` | Variables | バックエンドの死活確認の URL |
| `RAILWAY_TOKEN` | Secrets | Railway のプロジェクトスコープのトークン |
| `VERCEL_TOKEN` | Secrets | Vercel のトークン |
| `VERCEL_ORG_ID` | Secrets | Vercel の組織識別子 |
| `VERCEL_PROJECT_ID` | Secrets | Vercel のプロジェクト識別子 |

**バックエンドのドメインをワークフローへ書きません。** 隠蔽するためです。
