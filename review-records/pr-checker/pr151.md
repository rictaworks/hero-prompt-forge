## 4. 3 回のレビューで加わった内容の反映

指示のあった 5 点を、実装で裏取りしたうえで本文へ書き足しました。

1. **色の名前に明るさと鮮やかさを添える**
   `color_name.rb` の `modifier` と `config/color_names.yml` の `modifiers`（`deep_lightness: 0.35` / `pale_lightness: 0.72` / `muted_saturation: 0.40`）を確認しました。
   実測：`#D9C7A8` → `pale orange`、`#0B3D2E` → `deep green`、`#5F7F7A` → `muted teal`、`#001F5B` → `deep blue`、`#FFC0CB` → `pale pink`。
   修飾語は多くとも 1 つで、明るさを先に見ます。本文の対応表をこの実測に差し替えました。

2. **工程の順番を仕組みで守らせる**
   `ConflictResolver.integrated?` を関所として、次の 4 か所で止まります。
   - `rule_engine.rb#ensure_not_integrated!`（AI っぽさを避ける工程）
   - `style_spec.rb#ensure_not_integrated!`（絵のスタイルの仕様化）
   - `copy_space.rb#ensure_not_integrated!`（余白の確保）
   - `conflict_resolver.rb#ensure_not_integrated!`（二重適用の禁止）
   「控えには弱めて残したとあるのに実物からは消えている」という食い違いを、本文で説明しました。

3. **余白を確保していない案は統合できない**
   `conflict_resolver.rb#ensure_reserved!` が `CopySpace.reserved?` を見て `MissingCopySpaceError` を投げます。
   フォールバックで黙って補わない旨も書きました。

4. **絵のスタイルの配色指定とブランドカラーの衝突も、捨てずに弱める**
   `style_palette.rb` を確認しました。当てるのは `style_rules.values_for` が返す配色指定の値そのもので、部分一致ではありません。
   実測の置換後の文：`a restrained palette led by the brand accent`。

5. **設定の書き間違いを読み込みのときに見つける**
   `integration_rules.rb#ensure_placeholder!` が `Kernel.format` を実際に試し（`PLACEHOLDER_PROBE = 'gray'`）、
   差し込めない書き方を読み込み時に落とします。あわせて英文の形（`ENGLISH_TEXT_FORMAT`）、打ち消しの言い回し（`NEGATION_FORMAT`）、
   しきい値の逆転（`ensure_thresholds!` / `ensure_modifier_order!`）、色相の全周被覆（`ensure_continuous!`）を確認しました。
   `deep_freeze.rb` による入れ子の凍結も本文へ書きました。
