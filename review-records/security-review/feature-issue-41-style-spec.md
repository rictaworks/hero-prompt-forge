## PR #135 のレビューで得た観点を、最初から当てています

issue #40 のレビューで、**規則辞書は管理画面から人が編集するデータであり、中身を信用してはいけない**という観点が確立しました。この PR では、その観点を最初から組み込んでいます。

| 観点 | この PR での適用 |
|---|---|
| 辞書の中身を検める | 必須の項目が欠けている・空である・一覧が空である場合を、いずれも失敗させます |
| 内部の配列を外へ出さない | 避ける構図の一覧を複製して返します |
| 想定外の入力を握りつぶさない | スタイル系統の欠落・空文字・未定義を、いずれも失敗させます |
| 記録を残す | 適用したスタイル系統・指示の件数・避けた構図の件数を残します |
| 両方向で測る | 出すべき指示と、出してはいけない指示（他系統の指示）の両方を固定しています |

## 実施した検査

| 検査 | 方法 | 結果 |
|---|---|---|
| 資格情報の混入 | ステージ差分への正規表現検査（password / secret / api key / token / 私有鍵） | 検出なし |
| **撮影指示の欠落** | テスト | 実写系の必須5項目（レンズ・キーライト・フィルライト・リムライト・被写界深度）のいずれかが規則辞書に無ければ、その場で失敗させます。requirements.md 4.2 が「撮影指示を欠くプロンプトは出力しない」と定めています |
| 規則辞書の不備 | テスト | 項目が空文字・選べる値の一覧が空・必ず出す項目の一覧が無い・スタイル仕様化規則が空の4通りを、いずれも失敗させます |
| 想定外のスタイル系統 | テスト | 欠落・空文字・未定義のいずれも失敗させます。既定へ寄せません |
| 人物の破綻の回避 | テスト | 実写系では、顔や手指の破綻を避ける構図を必ず足します。避けた事実をノートへ残します |
| 規則の書き換え | テスト | 返した構図の一覧へ足しても、規則の中身は変わりません |
| 素材の作り方 | テスト | 1件1指示で足します。打ち消しの言い回しを作りません。日本語の素材を作りません |
| 下書きの引き継ぎ | テスト | すでにある素材と入力を持ち越します。もとの下書きを変えません |
| 例外に含める情報 | 目視 | スタイル系統・項目名・規則辞書の版のみです。利用者の入力・秘匿値を含みません。開発者向けの記述です |
| 記録に残す情報 | 目視 | スタイル系統と件数のみです。素材の中身を残しません |
| 文言の混入 | 検査 | 画面へ出す文言をこの層に持ちません。ハードコード検出テストが成功します |

## 判断したこと

**選べる値が一覧で書かれている場合は、先頭を既定として使います。** 並び順が既定の優先順です。3 案への展開（issue #50）で別の値を使う場合は、そちらが選び直します。この判断を実装の注釈へ残しています。

**素材は1件1指示で足します。** issue #40 のレビューで、1件へ複数の指示を詰め込むと、アンチAIルック規則が1つの語に当たったときに関係のない指示まで道連れになることが分かりました。issue #41 の申し送りとして受け取った内容を、実装の注釈とテストの両方で固定しています。

**日本語の素材を作りません。** 規則辞書の語が英語であり、生成モデルへ渡すのも英語のためです。日本語固有名詞の扱いは issue #44 が受け持ちます。

**打ち消しの言い回しを作りません。** 避けたい表現は、メインプロンプトではなくネガティブプロンプトの側で表します。

# セキュリティレビュー（2回目） : feature-issue-41-style-spec

- 実施日時（JST）：2026-08-26 22:00
- 差分の指紋：86588c4546bd48ab
- 対象：issue #41（初期データの不備への対応）

## 判定

合格

## 見つかった弱点

**実装を初期データで動かしたところ、そのままでは使えないプロンプトが出ることが分かりました。**

```
photoreal -> ["24", "soft key light from ...", ..., "back_view", "cropped_hands", "distant_figure"]
```

| 弱点 | 影響 |
|---|---|
| **レンズの焦点距離が `"24"` になっていました** | 初期データが数値の `24` を持ち、実装が黙って文字列へ直していました。生成モデルへ「24」とだけ渡っても、レンズの指示になりません |
| **避ける構図が `back_view` という内部の記号のままでした** | 生成モデルへ「back_view」と渡っても伝わりません。**顔と手指の破綻を避けるという、この機能の目的が果たされません** |

**テスト用の固定値だけで確かめていたため、気づけませんでした。** 固定値は英文で書いていたため、テストは通っていました。

## 直した内容

| 対応 | 内容 |
|---|---|
| 初期データを英文へ直しました | `24` → `35mm lens`、`back_view` → `the subject seen from behind` |
| 文字列でない値を失敗させます | 数値・真偽値・連想配列を黙って文字列へ直しません |
| 初期データを設定ファイルへ切り出しました | `config/rule_dictionary/initial.yml` に置き、`db/seeds.rb` とテストの両方が同じ内容を読みます |
| 初期データでの適用をテストへ固定しました | 4 系統すべてで指示を取り出せること、記号や数値だけの語が混ざらないことを確かめます |

## なぜ設定ファイルへ切り出したか

初期データは、**この製品の中核となる価値（AI っぽさを設計段階で外すこと）を担うデータ**です。`db/seeds.rb` の中に直接書かれていると、中身が仕様どおりかをテストから確かめられません。実際、今回の不備は「テストから読めなかった」ために見逃されていました。

**設定ファイルへ切り出したことで、seeds とテストが同じ内容を読むようになりました。** issue #137（初期データの中身を確かめるテスト）の土台にもなります。

## 実施した検査

| 検査 | 方法 | 結果 |
|---|---|---|
| 資格情報の混入 | ステージ差分への正規表現検査 | 検出なし |
| **初期データでの適用** | テスト・実測 | 4 系統すべてで、そのまま読める英文の指示が出ます |
| **記号や数値の混入** | テスト | 実写系の指示に、記号や数値だけの語が混ざらないことを確かめます |
| 文字列でない値 | テスト | 数値・真偽値・連想配列・一覧の中の数値を、いずれも失敗させます |
| 定義ファイルの不備 | 目視 | 読めない場合・鍵が足りない場合を、いずれも失敗させます |
| 定義ファイルの読み込み | 目視 | `YAML.safe_load_file` を使います。任意のオブジェクトを読みません |
| seeds の冪等性 | 目視 | 同じ版があれば何もしません。何度実行しても同じ結果です |
