## この変更の性質

**外から見える入口を 2 つ増やします。**

| 入口 | 誰が使うか | 認証 |
|---|---|---|
| `/health` | 外形監視サービス | **求めません** |
| `/admin` | 開発者 | **BASIC 認証** |

**認証を求めない入口と、開発者だけの入口を、同時に足します。** どちらも間違えると影響が大きいため、次の 3 点を重く見ました。

1. **管理画面が、資格情報の設定漏れで誰でも開ける状態にならないこと**
2. **死活監視の応答から、内部の作りが漏れないこと**
3. **利用者の認証で、管理画面へ届かないこと**

## 判断したこと

**管理画面の土台を、利用者向けの土台と分けました。** 利用者向けは `ActionController::API` で、画面を返しません。管理画面は画面を返しますので、画面を組み立てられる土台を継承します。**混ぜると、利用者向けの API に画面の仕組みが載ります。**

**死活監視に認証を求めません。** 求めると、監視サービスの設定に資格情報を置くことになり、資格情報の置き場所が増えます。**そのかわり、応答から内部の作りを消しました。**

**`/up`（Rails の既定）はそのまま残します。** 「アプリが起動しているか」だけを見る入口として、役割が違います。データベースへの到達は `/health` が答えます。

**まだ無い画面への導線を出しません。** 規則辞書の編集（#65）・利用者の管理（#66）・クォータのリセット（#67）・利用状況の集計（#68）は、それぞれの issue で足します。
