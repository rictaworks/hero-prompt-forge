# セキュリティレビュー（3回目） : feature-issue-62-64-ops

- 実施日時（JST）：2026-08-26 21:44
- 差分の指紋：dd020608e3de5574
- 対象：PR #150 の再確認で挙がった指摘への対応

## 判定

合格

## 直した内容

**`assume_ssl` を有効にしたことで、`force_ssl` が一度も働かない状態になっていました。**

`assume_ssl` は「すべての要求を TLS の上のものとして扱う」設定です。有効にすると、**平文の要求でも転送が起きません。** BASIC 認証の資格情報が、平文のまま流れます。死活監視を転送の対象から外す記述も、意味を持ちません。

| 指摘 | 対応 |
|---|---|
| **`assume_ssl` が `force_ssl` の転送を無効にします** | `assume_ssl` を明示的に無効にしました。配置先が付ける `X-Forwarded-Proto` を Rails が見て判断します |

## 実施した検査

| 検査 | 方法 | 結果 |
|---|---|---|
| 資格情報の混入 | ステージ差分への正規表現検査 | 検出なし |
| **本番の設定を実際に読み込んで確かめること** | テスト | `force_ssl` が真、`assume_ssl` が偽であることを、**本番の設定ファイルを読み込んで**確かめます。いまの環境の設定を見る形をやめました |
| 死活監視の除外が働くこと | テスト | 除外の判定を実際に呼び、`/health` が真、`/admin` が偽になることを確かめます |
| **管理画面が転送の対象であること** | テスト | 平文の `/admin` は転送されます。資格情報が平文で流れません |
| 書き方の検査 | RuboCop | 110 ファイル、指摘 0 件 |
| テスト | RSpec | 783 例、失敗 0 件 |

## 判断したこと

**`assume_ssl` を明示的に `false` と書きます。** 既定値に頼ると、将来だれかが「配置先が TLS を終端しているから」と有効にしたときに、**転送が黙って止まります。** 書いておけば、変えるときに理由を考えます。

**配置先が付ける印を信じます。** Railway は TLS を終端し、`X-Forwarded-Proto` を付けて渡します。Rails はその印を見ますので、**印がある要求は転送されず、印の無い平文の要求だけが転送されます。**
