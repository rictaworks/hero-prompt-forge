### 経緯

3 回目（HTML の実測方式）も CI（`33239266017`）で不合格でした。原因を
`docker compose cp` で本番相当ビルドの実際の HTML を取り出して確認したところ、
`/requests/new` は `useSearchParams()` を使うため **Next.js が
`BAILOUT_TO_CLIENT_SIDE_RENDERING`（クライアント側だけで描く扱い）にしており、
本番の組み立てでは送信ボタンを含む入力フォームそのものが最初の HTML に
含まれていません**（`<p>読み込んでいます。</p>` という代わりの表示だけが
入っています）。**この画面が実際にサーバーで描かれるのは開発サーバー
（`npm run dev`）のときだけです。** そのため「サーバーが描いた HTML を見る」
という確かめ方は、本番相当の組み立てでは成立しませんでした。

**タイミングにも、描画の方式にも依存しない形へ作り直しました。**
`domcontentloaded` の直後という最も早いタイミングで、実際に送信ボタンへ
素のクリックを送り込み、その結果として `?` を含む URL（実測された不具合の
症状そのもの）へ遷移しないことを直接確かめます。手元で **開発サーバー
（`npm run dev`）・本番相当の組み立て（`npm run start`）の両方**で 3 例とも
成功することを確認しました。

`NewRequestForm.tsx` のコメントも、開発サーバーでだけ実際にサーバー側で
描かれる旨へ書き直しました（実装の動きは変えていません）。
