## レビューの指摘への対応

### 要修正 1（`project_id` を配列で送ると 500 になります）

**`params.expect(:project_id)` へ揃えました。** `params.require` は配列をそのまま通しますので、`find` が配列を返し、契約の形を外れた 500 になっていました。

### 要修正 2（`project_id` が無いと契約の形で返しません）

**2 回目の記録は、この対応を「足しました」と書いていましたが、実際には入っていませんでした。** 同じ変更を、別のブランチ（PR #167）へ書いてしまっていました。**2 回目のレビューで、コードに 1 件も無いことを実測で指摘されました。**

**3 回目で、`BaseController` へ `rescue_from ActionController::ParameterMissing` を実際に足しました。** `invalid_input`（400）として、`code` ・ `message` ・ `next_action` を備えた形で返します。**添えるのは項目名だけです。** 送られた値を返しません。

**テストも足しました。** 識別子が欠けている場合・配列の場合・連想配列の場合の 3 通りについて、**状態コードだけでなく、契約の 4 項目がそろうこと・項目名が添うこと・記録も枠も作らないこと**を固定しました（18 例）。

**`rescue_from` を外すと、そのうち 9 例が赤くなります**（契約の形を押さえた例です）。**残る 9 例は緑のままです。** 状態コードと副作用の無さを押さえており、Rails の既定でも満たされるためです。**役割が違いますので、赤くならないのが正しい姿です。**

**記録の書き方を改めます。** 「テスト」と書くのは、**そのテストを実際に走らせて緑になったときだけ**にします。

### 要修正 3（`details.reasons` の中身が SPEC と食い違います）

**契約へ例外を明記しました。** 「要求した本人が送った入力の写しは含めます。記録には残しません。第三者の情報・秘匿値は、いかなる場合も含めません」と書き、`422` の `details` の中身を表にしました。**画面側で逃がす（エスケープする）ことも書き添えました。**

### 要修正 4（差し戻した記録に原文が残ります）

**差し戻した記録から `service_summary` を落とします。** 見つかった語を理由に残さない配慮は、**原文がそのまま別の列に残っていては意味がありません。** 権利に触れると判定した文章ですので、実在の方のお名前や商標を含みます。**生成には使いません。** 業種・スタイル系統といった選択肢の値は、入力し直していただくときの手がかりとして残します。

### 要修正 5（順序の固定が返還済みの枠を捉えません）

**件数ではなく状態で確かめる例を足しました。** 返還済みの枠がある日に禁止入力を送っても、**枠は `refunded` のままです。**

### 要修正 6（上限到達の時刻テストが日付を固定していません）

**`travel_to` で 02:59:59 と 03:00:00 を作り、完全一致で確かめます。**

### 要修正 9（PR 本文のユーザーテストが実行できません）

**PR 本文の入口を `http://localhost:3301/...` へ直しました。** `ENV/DEVELOPMENT.md` のとおり、ホスト側は 3301 です。**3000 番には別のリポジトリが載っています。**

## 判断したこと

**禁止入力の判定を、枠の予約より先に置きます。** 順序が入れ替わると、断った利用者の枠が減ります。

**枠の予約を、状態を進めるより先に置きます。** `queued` から `rejected` へ戻る道はありません。

**受付をトランザクションで包みません。** 予約は上限到達の測定を伴います。**包むと、断った事実の記録だけでなく、本業の変更まで巻き戻り、しかも呼び出す側は成功を受け取ります**（PR #164 の申し送り）。

**他人の資源へは 404 を返します。**

**プラン値の判定を、入力を読む前に行います。**

**見つかった語は、応答では返し、記録には残しません。** 応答は要求した本人にだけ返ります。**どの語で止まったのかが分からないと、1000 文字の文章を直せません。**

## 申し送り

**`failed` から `queued` への再実行の入口は、この PR に含みません。**

**一覧の取り出しは、この PR に含みません。**

**断られた要求の記録は、枠では止まりません。** 枠を使い切った状態でも `draft` が、禁止入力でも `rejected` が積み上がります。**この入口が本番へ出る前に、reCAPTCHA（issue #61）を通してください。**

**運用で起こり得る失敗（公開済みの規則辞書が無い等）は、いまは 500 になります。** 503 で契約の形へ寄せることを、別途ご検討ください。
