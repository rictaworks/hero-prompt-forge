## 判断したこと

**禁止入力の判定を、枠の予約より先に置きます。** requirements.md 4.1 の 1 は「差し戻し時はクォータを消費しない」と定めています。**順序が入れ替わると、断った利用者の枠が減ります。** テストで順序を固定しました。

**枠の予約を、状態を進めるより先に置きます。** `queued` から `rejected` へ戻る道はありません（requirements.md 12.1）。先に進めると、枠を取れなかったときに戻せない記録が残ります。

**受付をトランザクションで包みません。** 予約は上限到達の測定を伴います。外側のトランザクションで包むと、断った事実の記録まで巻き戻ります。

**他人の資源へは 404 を返します。** 403 を返すと、識別子を変えながら試すことで**他人の資源の存在の有無**が分かります。

**プラン値の判定を、入力を読む前に行います。** 入力の誤りを先に返すと、**権限の無い方に対して入力の検証器として働きます。**

**見つかった語を、応答では返し、記録には残しません。** 応答は要求した本人にだけ返ります。**どの語で止まったのかが分からないと、1000 文字の文章を直せません**（requirements.md 4.1 の 1 が求める代替表現の提示です）。**記録は保管期間が長く、閲覧できる範囲も広くなります**ので、種別だけを残します。

**差し戻した理由の中身を、取り出しの応答へ出しません。** 記録に残るのは開発者向けの種別です。利用者へは文言と次に行う操作を返します。

**受け取る項目を、正規化が通したものだけに絞ります。** `params` を直に `create!` へ渡しません。**想定していない列を書き換えられません。**

## 申し送り

**`failed` から `queued` への再実行の入口は、この PR に含みません。** requirements.md 12.1 は同一リクエストの再実行を定めており、**追加のクォータを消費しません。** 入口を作る際は、返還済みの枠を取り直す `Quota::Reservation.reserve!` を通してください。

**一覧の取り出し（`GET /api/v1/prompt_requests`）は、この PR に含みません。**
