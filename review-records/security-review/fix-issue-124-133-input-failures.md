## この変更の性質

**利用者の入力が最初に触れる層です。** issue #55 で入口を作ると、ここへ外部からの値がそのまま届きます。次の 3 点を重く見ました。

1. **想定外の形の入力で、理由の分からない失敗にならないこと**
2. **同時に呼ばれても、他人の入力の結果が混ざらないこと**
3. **記録に利用者の入力そのものを残さないこと**

## 判断したこと

**ブランドカラーの空の要素は、未指定として落とします。** 同じ色の重ねがけとは扱いを分けます。空の欄は「指定していない」ことの素直な表れです。同じ色を 2 度書くのは「2 色指定したつもり」との食い違いですので、黙って減らさずに誤りとして返します。**揃えない理由をテストの注釈へ残しました。**

**呼び出しの途中の状態を `Attempt` へ移しました。** 呼び出しごとに作り直すため、使い方に依存しなくなります。選択肢の定義（`InputChoices`）は、これまでどおり `InputNormalizer` から引けます。

**追加した文言は、実際に使っている検証の分だけです。** 使っていない検証の文言を先回りして足しません。足りなくなればテストが知らせます。
