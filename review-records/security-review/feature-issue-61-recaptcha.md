## 秘匿値の扱い

**秘密鍵を環境変数（`RECAPTCHA_SECRET_KEY`）から読みます。** ソースにも設定ファイルにも書きません。`.env.example` は空欄だけを置きます。

**秘密鍵を URL へ載せません。** 本文（form）で送ります。**URL は記録へ残ります。** テストで固定しました。

**鍵が無ければ、その場で失敗させます。** 既定へ寄せると、**照合したつもりで照合していない状態**になります。

**サイト鍵は秘匿値ではありません。** ブラウザから見える値ですので、`NEXT_PUBLIC_RECAPTCHA_SITE_KEY` として分けて書きました。

## 判断したこと

**Bot 対策を自作しません**（CLAUDE.md）。判定は reCAPTCHA へ委ねます。**v3 を使います。** 利用者に絵を選ばせません。

**合図は見出しで受け取ります。** 本文へ混ぜると、入力の項目として記録へ流れます。**合図は認証の材料であって、生成の入力ではありません。**

**投入する経路だけを守ります。** 閲覧の経路は守りません。画面を開くたびに合図を求めると、**上限に達した方が履歴すら見られなくなります。**

**本番では必ず照合します。** 秘密鍵が設定されていなければ、その場で失敗させます。**鍵の入れ忘れで Bot 対策が黙って無効になる状態を作りません。**

**開発とテストでは、鍵が設定されているときだけ照合します。** 手元で画面を触るたびに Google の鍵を要求しないためです。**この分かれ方は環境だけで決まります。** 要求側の値（見出し・引数・クッキー）では切り替わりません。**本番の画面に、飛ばす導線を出しません。**

**通らなかった理由を利用者へ返しません。** Google が返す理由の符号は、Bot 対策の内側の情報です。**返すと、通り抜け方を探る手がかりになります。**

**照合そのものができない場合と、通らなかった場合を分けます。** 前者は 503（利用者の落ち度ではありません）、後者は 403 です。

**得点の下限も待ち時間も、設定ファイルへ置きます。** 運用で変わります。**厳しくすると本当の利用者を弾き、緩めると Bot を通します。**

**行動の名前を確かめます。** 確かめないと、別の画面で取った得点を使い回せます。

## 申し送り

**画面側（Next.js）の組み込みは、この PR に含みません。** サイト鍵を `NEXT_PUBLIC_RECAPTCHA_SITE_KEY` から読み、行動の名前 `generate_prompt` で得点を取り、`X-Recaptcha-Token` の見出しで送ってください（issue #71）。

**本番の秘密鍵は Railway の変数へ入れてください。** 未設定のまま本番を動かすと、投入の経路がその場で失敗します。

**画面側（issue #71）では、次の 2 点にご注意ください。**

- **CSP が `https://www.google.com/recaptcha/` と `https://www.gstatic.com/` を許す必要があります。**
- **バックエンドを隠す中継が `X-Recaptcha-Token` を素通しする必要があります。** 同一の生成元からの呼び出しを前提としています。

**本番で鍵が無いことに、起動時には気づけません。** 最初の投入の要求まで分かりません。**初期化時の確認は、別の機会に検討します。**

**`503` に `Retry-After` を添えていません。** 画面側が再試行の間隔を決められるようになりますので、別の機会に検討します。

**同じ判断の文章が、コードの注釈・契約・PR 本文・記録の 4 か所にあります。** 正は `SPEC/api/README.md` です。**直すときは、そこから直してください。**

**`.env.example` は、この PR と PR #170 が同じ位置（`GEMINI_API_KEY=` の直後）へ差し込みます。** 後にマージする側で衝突します。**両方の節を残して解いてください。**

**開発の分岐（鍵があるときだけ照合する）は、PR #170 のマージまで手元で試せません。** `docker-compose.yml` への配線が #170 に含まれるためです。**その間は「鍵が無いので飛ばす」側だけが動きます。**
