## 判断したこと

**持ち主を、要求の値で決めません。** 作成では `user: current_user` を固定で渡します。`user_id` を送っても自分のものになることを、テストで固定しました。

**引くところを、必ず `for_user` に通します。** 絞り込みを飛ばす経路を作りません。評価メモは**案で絞ります。** メモは案に属しますので、案の持ち主が決まればメモの持ち主も決まります。**メモの識別子で直に引く経路を作りません。**

**他人の資源は 404 です。** 403 を返すと、識別子を変えながら試すことで**他人の資源の存在の有無**が分かります。

**プリセットの入力条件を、コントローラで絞りません。** 許される鍵は `Preset::ALLOWED_CONDITION_KEYS` が持ちます。**二重に書き写すと、片方だけを増やしたときに食い違います。**

**検証の失敗では、項目名と理由だけを返します。** 値を返しません。返すと、入力の内容が失敗の記録へ流れます。

**プロジェクトとプリセットを消す経路を作りません。** プロジェクトには生成履歴が結び付いています。

**生成履歴の一覧に、案そのものを載せません。** 件数が増えるほど応答が重くなります。**取り出しは 1 件ずつ行います。**

**閲覧と記録の経路に、枠の判定を置きません。** requirements.md 4.4 は上限到達でも閲覧・記録できることを求めています。

## 申し送り

**`inputs` を返す経路がありません。** 生成履歴から「複製」（同じ条件での作り直し）を行うには、条件を取り出せる必要があります。**別の issue で扱います。**

**先読み（`includes`）を外しても、テストが赤くなりません。** 性能のための書き方が、あとで消えても気づけません。**問い合わせ回数を数えるテストを、別の機会に足してください。**

**`rescue_from ActiveRecord::RecordInvalid` を 3 つのコントローラで書き写しています。** 新しいコントローラで書き忘れると 500 になります。**基底へ寄せることを、別の機会にご検討ください。** あわせて `ActiveRecord::RecordNotUnique` も受け止めると、形の外れる経路が無くなります。

**評価メモを消す経路は、この PR に含みません。**

**`tone` ・ `colors` は、まだどこからも読んでいません。** 読むのは `people` だけです。**読む場所ができた時点で、値の形（カラーコードであること・最大 2 色であること）も検めてください**（requirements.md 4.1）。いまは大きさでしか止まりません。

**呼び名がプリセットの側（`brand_tone` ・ `brand_colors`）と食い違います。** 読む場所を作るときに揃えてください。

**決まっていない鍵を既に持つプロジェクトは、名前だけの更新でも 400 になります。** いまはそのようなデータを作る経路がありませんので実害はありません。**歯止めを入れる前のデータがある環境では、先に確かめてください。**

**上限は「JSON にしたときの長さ」です。** 鍵の名前ぶんが引かれます。画面側が文字数を数えるときは、値そのものの上限を別に決めてください。

**`Preset::MAX_CONDITIONS_LENGTH` は、サービス概要の上限（1000 文字）と独立した値です。** 片方だけを増やすと食い違います。**別の機会に、後者から導出することを検討してください。**

**新しい歯止めを赤くしているのは、モデルのテストだけです。** API を通して 400 になることは手で確かめました。**別の機会に、リクエストのテストへも 1 例ずつ足してください。**

**生成履歴の頁分け（ページネーション）は、この PR に含みません。** 件数が増えたら足します。
