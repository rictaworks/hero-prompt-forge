# セキュリティレビュー（3 回目）: 案に添えるノートの形を直します

- 実施日時（JST）：2026-08-27
- 差分の指紋：7763a05ee2dca6d9
- 対象：確認用の記録の作り方

## 直したこと

**調整の案（`adjustments`）を、連想配列から文字列の並びへ直しました。**

`Generation::AdjustmentList#build` は**文字列の並び**を返します（`draft.notes.filter_map { ... }`）。画面もそれを前提に、要素をそのまま置きます。**連想配列を渡すと、画面が「そのまま出せないもの」を受け取り、React が組み立てに失敗します**（`Minified React error #31`）。

**結果 3 案の画面が丸ごと落ちていました。** 逃がし先（`error.tsx`）が受け止め、「想定していない問題が起きました。」を出していました。

## 確かめたこと

| 観点 | 方法 | 結果 |
|---|---|---|
| 記録の形 | 実測 | API の応答で `adjustments` が文字列の並びになりました |
| ブラウザ操作の確認 | Playwright | **47 例すべて緑**（`test/pr-setup` 2 例 ・ `test/pr170` 9 例 ・ `test/pr174` 36 例） |
| 上限到達の確認 | Playwright | **緑です。** 枠を確定させた記録を用意しても、確認の側は通ります |
| 秘匿値の混入 | 目視 | ありません |
| 外部への通信 | 目視 | ありません |

**手元で、自動検査と同じ手順を再現して確かめました。** 空のデータベースを作り、規則辞書を入れ、自動ログインの利用者を 1 名作り、この手順で記録を用意し、組み立て済みの画面（`next start`）に対して流しました。

## 気づいたこと（次の issue へ）

**画面が落ちても、ブラウザ操作の確認の記録が残りません。** 逃がし先が「想定していない問題が起きました。」を出すため、**「何が出ていないか」は分かっても「なぜか」が分かりません。** 原因に辿り着くには、ブラウザの記録（コンソール）を別に採る必要がありました。**失敗時に Playwright の成果物（スクリーンショット・追跡・報告書）を残す手順を、次の issue で足してください**（PR #179 のレビュー・提案 4）。

連絡先は info@rictaworks.jp です。
