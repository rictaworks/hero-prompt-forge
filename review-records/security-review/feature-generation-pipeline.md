## 直したこと

**要修正 1：`config/llm.yml` の `endpoint` が効かない状態を直しました。**

`langchainrb` は呼び出し先を gem の中で組み立てます。そのままでは、**設定を直しても呼び出し先が変わりません。** 「暗号化された通信だけを認めます」という検め（`LlmSettings.ensure_endpoint!`）が、**実際の呼び出し先を守らない状態**でした。**設定の呼び出し先だけを使うように改めました。**

**要修正 2：実際に入る版の公開日と、二択の比較を書きました。**

| 事実 | 値 |
|---|---|
| 入る版 | **0.19.5**（`Gemfile.lock` で確認しました） |
| その版の公開日 | **2025-05-01**（RubyGems の版の一覧で確認しました） |
| いまからの経過 | **約 16 か月** |
| 最新の公開版かどうか | **最新です。** 0.19.5 より新しい公開版はありません |
| 先端の書き換え | 続いています（最終の push は 2026-08-26） |

**「先端が活発であること」と「入る版が新しいこと」は別です。** 公開版は 16 か月出ていません。

**それでも採る理由を 2 つ書きました。** 呼び出しの要所（呼び出し先・鍵の送り方・待ち時間・送る内容）をこちらで押さえていること、使っているのが 1 クラスだけで離脱できることです。**Python の別サービス（FastAPI ＋ 本家の LangChain）との比較も書きました。** サービスが 1 つ増える負担に対し、いま AI の呼び出しは 1 系統だけですので、CLAUDE.md の「必要な場合のみ FastAPI を足す」という条件を満たしません。

**要修正 3・4：テストが狙った場面を作れていなかった箇所を直しました。**
