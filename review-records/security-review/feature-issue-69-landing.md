## レビューの指摘への対応

### F1【重大】ランディングを開いただけで、ログインの手続きが始まります

**外への出口を、素の入口で描くようにしました。** 画面の中の移動の仕組み（`next/link`）は移動先を先に読み込みますので、**利用者が何も押していないのに `/auth/start` が呼ばれ、認可の途中の値を書き込む Cookie が毎回書き換わっていました**（PR #170 のレビューで実測されました）。

**影響は 3 つありました。**

1. **間欠的にログインできない不具合の原因になります。** 先読みの応答が、押した後の応答より遅れて届くと、照合値が一致しません。
2. **同意の前に、訪問者のブラウザが X へ要求を出します。**
3. **ランディングの表示回数と同じだけ、認可の開始が発生します。**

`Button` へ `external` を足し、外への出口では素の入口を描きます。

### F2【重大】ブラウザ操作のテストが失敗します

**見出しを完全一致で探すようにしました。** 「From Input to Package」が「Input」を含むためでした。

### R2 添え書きがモックと違います

**改行の位置と、アカウント名の色（金）を、モックへ合わせました。** アカウント名は「誰のフォロワーであればよいか」という判断材料ですので、周囲と同じ灰色に沈ませません。

### R3 公開画面としての必須の設定

**OGP（題・説明・画像・種別・場所）と canonical を足しました。** 公開先は `NEXT_PUBLIC_BASE_URL` から引きます。**これはブラウザへ配ってよい値です。** 未設定なら、その場で失敗させます。

### R4 画像の出どころとライセンスの記録

**`src/frontend/public/images/README.md` へ書きました。** 出どころ・中身を変えていないこと・**利用条件が未確認であること**・確認が取れない場合は AI 生成へ差し替えることを書きました。

### R5 文言の検査が、変異試験で抜けます

**語尾で見る形へ改めました。**

- 文は「です。」「ます。」「ません。」「ください。」「ますか？」等で終わることを検めます。**終わりの記号だけを見ると、「だ・である調」が句点付きで素通りします。**
- `labels` は**述語で終わらない**ことを検めます。**長さと句点の有無だけでは、「だ・である調」の短い文が素通りします。**
- **「含む」ではなく「終わる」で見ます。** 「フォロワーであること」のような名詞のまとまりは、条件の言い表し方として正しいものです。

**モックの見出し「第一印象を、業務品質に。」は体言止めです。** 句点で終わりますが述語を持ちませんので、**対象から外す場所へ明示して書きました。** モックは書き換えません。

### R6 公開画面に他社の名称が出ます

**`hero-prompt-forge` へ直しました。** モックの既定値（デザインシステムの名前）をそのまま公開しません。**モックは書き換えていません。正しい値は実装側で入れます**（CLAUDE.md）。**ブランドが確定したら、そこを直します。**
