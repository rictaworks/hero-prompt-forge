## 判断したこと

### 1. 要求元のアドレスを、Google へ送りません

**`remoteip` は照合 API の任意の項目です。** 送らなくても照合は成立します。**送るのをやめます。**

| 観点 | 判断 |
|---|---|
| 得点の精度 | **そのぶん下がります。** 認めます |
| 守りが足りるか | **足ります。** 投入の経路は X ログインとプラン値で守られています。**誰でも投げられる経路ではありません** |
| ほかの守り | 1 日あたりの生成枠、禁止入力の検出、reCAPTCHA の得点 |
| 方針との整合 | `requirements.md` 5.3 は「**保持する個人関連情報は X のユーザー ID と表示名のみ**」と定めます。**アドレスを第三者へ渡すのは、この方針から外れます** |

**受け取って捨てる形にしません。** 引数そのものを置かないことで、**渡した時点で失敗します。** 受け取って捨てると、呼び出す側は「送っている」と思ったままになります。

### 2. 特定商取引法に基づく表示は、義務ではありません

**本サービスは無償で提供します。** 対価を得る取引がありませんので、**法律上の表示義務はありません。**

**それでも置きます。** 提供者と連絡先を自主的に示すためです。**「義務があるから」ではなく「どこの誰が提供しているかを示すため」**として書いています。

### 3. 置き場は、画面の一部にします

**別の文書（Markdown）にしません。** issue #172 の受け入れ条件は「**画面から辿れること**」です。文書と画面の二重管理にすると、**片方だけが古くなります。**

### 4. 導線は、ランディングの下の帯に置きます

**モック（`app-ui/index.html`）には無い要素です。モックは書き換えません。** 実装側で足します。

**ログインの前に辿れる位置に置きます。** Cookie を置くのはログインの時点ですので、**その前に読める必要があります。**

**ログインした後の画面への導線は、この PR に含めません。** ログイン後の共通の枠（`AppShell`）へ帯を置くかどうかは、**モックに無い要素をどこまで足すかの判断**であり、designer に諮る必要があります。**公開のランディングから辿れれば、受け入れ条件は満たします。** 別 issue で足します。

### 5. Google への導線は、プライバシーポリシーに置きます

**reCAPTCHA v3 のバッジを隠していません。** バッジには Google の規約とポリシーへの導線が含まれます。**それに加えて、プライバシーポリシーからも辿れるようにします。** 隠す判断をした日に、代わりの表示が既にある状態にしておきます。

連絡先は info@rictaworks.jp です。
