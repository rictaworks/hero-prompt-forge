## 4. 指摘

### 要修正 1：`project_id` を配列で送ると 500 になります

`params.require(:project_id)` は配列をそのまま通します。`find([1, 1])` が配列を返し、`create!(project: 配列)` で落ちます。**ログインした利用者であれば誰でも引き起こせます。** `params.expect(:project_id)` へ揃えてください。

### 要修正 2：`project_id` が無いと、契約の形で失敗を返しません

`ActionController::ParameterMissing` が素通りし、`code` / `message` / `next_action` を持たない応答になります。`BaseController` へ `rescue_from` を足してください。

### 要修正 3：`details.reasons` の中身が SPEC と食い違います

SPEC 側に「`details` には要求した本人の入力の写し（`matched`）を含めます。第三者の情報は含めません」と例外を明記し、エンドポイントの表へ `matched` と `prompt_request_id` を書き足してください。

### 要修正 4：差し戻した記録に、サービス概要の原文が残ります

`matched` を記録に残さない判断の根拠は「記録は保管期間が長い」でした。**ところが `matched` を含む原文そのものが、同じ記録の別の列（`inputs`）に残ります。** 配慮が効いていません。

### 要修正 5：順序の固定が、返還済みの枠を取り直す道筋を捉えません

件数ではなく状態（`refunded` のまま）で見る例を足してください。

### 要修正 6：上限到達の時刻テストが、日付を固定していません

`travel_to` を用い、02:59:59 と 03:00:00 で `details.reset_at` を完全一致で確かめてください。

### 提案

- 時刻の書式を `time.formats.*` と `I18n.l` へ寄せられます。
- `errors.forbidden_input.message` と `prompt_requests.failure.rejected.message` が同じ文です。
- 断られた要求の記録が際限なく増えます。**この入口が本番へ出る前に #61 を通す**必要があります。
- `RuleDictionary::MissingCurrentError` 等が 500 になります。運用で起こり得る失敗は 503 で契約の形へ寄せることをご検討ください。
- `test/pr166/` がありません。運用として揃えるか、README を実態へ合わせるかを決めてください。
