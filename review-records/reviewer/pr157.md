## 2. 重大な指摘（マージ前に直してください）

### 2-1. 打ち消しの窓を 12 文字へ広げたことで、止めるべき文を新たに取りこぼします

**該当**：`src/backend/config/forbidden_inputs.yml:114` ・ `:116`
`(?![^。、]{0,12}(?:、[^。、はが]{0,8})?(?:ません|ないで|ず(?!み)|禁止|不可|不要|かね|控え|避け|遠慮))`

**測った結果**（同じ素材を `222fbf9` と `fb1f536` で実行しました）。

| 文（いずれも他社ロゴの掲載指示です） | `222fbf9` | `fb1f536` |
|---|---|---|
| 他社のロゴを大きく載せて加工を控えめにしてください。 | 止める | **通す** |
| 他社のロゴを中央に配置して余白を不要なほど詰めます。 | 止める | **通す** |
| 他社のロゴをそのまま使い色数は控えめにします。 | 止める | **通す** |
| 他社のロゴを載せてほしいのですが不可能でしょうか。 | 止める | **通す** |
| 他社のロゴを大きく載せ、加工を控えめにしてください。 | 止める | **通す** |
| 他社のロゴを中央に配置し、余白を控えめに取ってください。 | 止める | **通す** |
| 他社のロゴを載せてください、遠慮はいりません。 | 止める | **通す** |
| 他社のロゴを大きく載せてください、装飾を控えめに。 | 止める | **通す** |
| 他社のロゴをそのまま使い、色だけを控えめにします。 | 止める | **通す** |
| 他社のロゴを配置し、文字を不要なほど小さくします。 | 止める | **通す** |
| 他社のロゴを配置して禁止事項は特にありません。 | 通す | 通す（基準から変わりません） |

**原因は 2 つあり、どちらも新しい窓の作りに由来します。**

1. **窓が 12 文字になったこと自体**です。読点をまたがない文でも、`控え` `不要` `不可` が意図の語の 12 文字以内に入るだけで打ち消しと読みます。**「〜を控えめに」「〜を不要なほど」は、デザインの指示文でごく普通に使う言い回しです。**
2. **読点をまたぐ例外の条件が緩すぎます。** 守りは「読点の先に `は` `が` が現れない」だけですので、**「、装飾は不要です」は守れますが、「、装飾を控えめに」「、余白を控えめに」は素通り**します。助詞が `を` `に` `で` へ変わるだけで守りが外れます。

**PR の計測素材が、この穴をちょうど避けています。** 足された 2 件（`、装飾は不要です` ・ `、余白は控えめにします`）は、いずれも読点の先が `は` の形だけです。**`を` `に` の形を 1 件も含みません。**（TM：同値分割の代表値が 1 つの類だけに偏っています。12 文字という窓幅の境界値も測っていません）

issue #148 の受け入れ条件「**検出側を痩せさせません**」に反します。また、この検出は第三者のロゴ・商標という権利の関門ですので、取りこぼしの重さは誤検出と同じではありません（QC10・CC の観点に抵触します）。

### 2-2. 会社名の本体から「の」を外したことで、「の」を含む会社名を 1 文字前後まで切り詰めます

**該当**：`src/backend/config/proper_nouns.yml:75-78`
`([ぁ-ゖァ-ヴー一-龥A-Za-z0-9&&[^の]]{1,20}?(?:の(?:%<name_words>s))?)(?=が|は|を|に|で|と|へ|も|の|、|。|\s|$)`

**測った結果**（同じ素材を `222fbf9` と `fb1f536` で実行しました）。

| 文 | 正しい名前 | `222fbf9` | `fb1f536` |
|---|---|---|---|
| 株式会社みのりが運営します。 | みのり | みのり | **み** |
| 株式会社きのこは製菓会社です。 | きのこ | きのこ | **き** |
| 株式会社たけのこをご紹介します。 | たけのこ | たけのこ | **たけ** |
| 株式会社ひのでは製菓です。 | ひので | ひの | **ひ** |
| 株式会社このはが運営します。 | このは | この | **こ** |
| 株式会社あけぼのが運営します。 | あけぼの | あけぼの | **あけぼ** |
| 株式会社ものづくり研究所です。 | ものづくり研究所 | ものづくり研究所 | **も** |
| 株式会社いのちの木が運営します。 | いのちの木 | いのちの木 | **い** |
| このはな株式会社が運営します。 | このはな | このはな | **はな** |
| きのこ株式会社です。 | きのこ | きのこ | **こ** |

**仕組みは次のとおりです。** 本体から `の` を外し、先読みへ `の` を足したため、**照合は最初の `の` で必ず止まります。** `の` をまたげるのは、**直後が `name_forming_words` の 1 語で、しかもその次が区切りである場合だけ**です。したがって、

- `みのり` `きのこ` `ものづくり` のように **`の` が語中にある名前**は、すべて頭で切れます。
- `いのちの木` のように **`の` が 2 回現れる名前**は、1 つ目の `の` で切れます（`name_forming_words` は後ろの `の` にしか効きません）。
- 前置きの形（`きのこ株式会社`）では、**照合の開始位置が `の` の後ろへずれ、名前の後半だけ**（`こ`）を拾います。

**この結果は「取りすぎるより短く切るほうが害が小さい」では正当化できません。** 拾った名前は日本語のまま生成モデルへ `み (a company name)` として渡ります。**存在しない社名を作って画へ焼き込むという点で、`みらいの強み` を拾う不具合と同じ種類の害**です。長さの下限（たとえば 2 文字未満は名前として扱わない）も置かれていません。

issue #153 の受け入れ条件「**両方向で測ります**」に反します。`scripts/measure/proper_noun_coverage.rb` の `spanning`（4 件）は **すべて `name_forming_words` に載る語で終わる名前**であり、**上の類（語中に `の` を含む名前）の素材が 1 件もありません**。

## 3. 要修正の指摘

### 3-1. 一覧の語を、逃がさずに正規表現へ差し込みます

**該当**：`src/backend/app/services/generation/proper_noun_rules.rb:44-51, 85-87`

`name_words_of` は `words.all?(String)` しか見ず、`matcher_for` は `words.join('|')` をそのまま `gsub` の置換文字列として差し込みます。

- **空文字列を弾きません。** `name_forming_words` に空の要素が 1 つ混ざると `(?:の(?:家||舎))?` となり、`の` だけをまたげてしまいます。
- **正規表現の記号を逃がしません。** `(` や `|` を含む語を書かれると、手がかり全体の意味が変わります。
- **`gsub` の置換文字列では `\0` `\1` `\\` が特別扱いされます。** `Regexp.union` を使うか、`gsub` をブロック形式にしてください。

同じ PR の `word_forms_table.rb:60-73` は値の形（`ASCII_WORD`）まで検めています。**同じ厳しさをそろえてください**（DP：surprise の少ない構造・Fail Fast）。

### 3-2. 起動時に検める対象へ、`proper_nouns.yml` を含めます

**該当**：`src/backend/config/initializers/generation_definitions.rb:12-15`

読み込むのは `Generation::WordForms` だけです。**この PR は `proper_nouns.yml` へ必須の鍵 `name_forming_words` を新たに足し、無ければ例外にしています。** 起動時に読まないため、**この鍵が欠けても最初の生成まで気づけません。** issue #148 の 4 番目の目的（不備に起動時に気づく）が、同じ PR で入れた新しい必須項目には及んでいません。

### 3-3. `reset!` の説明と、実際の呼び出し先が食い違います

**該当**：`word_forms.rb:80-83` と `generation_definitions.rb:14`

`reset!` には「**本番の経路では使いません**」と書いてありますが、起動時の initializer（本番の経路）から呼んでいます。**説明とふるまいのどちらかを直してください**（DP：コメントより読みやすいコード／surprise の少ない構造）。

## 4. 提案

- **4-1.** `word_forms.rb:57-63` は、そろえ終えた値を `traced(applied) { canonical }` で包んでいます。**囲まれた塊は何もしません**ので、`Trace.step` の「失敗」の経路は決して通りません。そろえる処理そのものを囲むか、`Trace` を使わず 1 行の記録に留めるほうが、意図が伝わります。

- **4-5.** 会社名の切り出しには、この PR とは別に、以前からの取りすぎが残っています。`弊社は株式会社です。`→`弊社は`、`株式会社への変更をお手伝いします。`→`へ`、`合同会社から株式会社へ組織変更しました。`→`合同会社から` ・ `から株式会社`。**`株式会社` などが普通名詞として出てくる文**を、`untouched` の素材へ足すことをおすすめします。
- **4-6.** `ず(?!み)` の副作用として、`他社のロゴを配置せずみやすい画面にしてください。` が新たに止まります（基準では通りました）。読点のある書き方なら通りますので実害は小さいと見ますが、素材へ残しておくと後戻りに気づけます。

**取りすぎより害が小さいとは言えません。** 名前が拾われないと、**その社名はローマ字にも直されず、日本語の名前を守る仕組み（requirements.md 4.1 の 6）が働きません。** お客さまの社名が、そのままヒーローイメージの指示から落ちます。

**守りたかったのは、`弊社は` ・ `への変更` ・ `から株式会社` の 3 つの形です。** それは**拾ったあとで判断**できます。

- 「株式会社への変更をお手伝いします。」は、いまの落とす仕組みで `への変更` → `へ` まで縮みます。**「縮んだ結果が助詞 1 文字だけなら捨てる」**で足ります。
- 「弊社は株式会社です。」は、**会社そのものを指す語（弊社・当社・自社・御社・貴社・わが社）で始まる名前を拾わない**、という語彙の守りで足ります。

**いずれも「名前の先頭・末尾の 1 文字が助詞かどうか」ではなく、「その名前が会社名として意味を成すか」で判断する形です。** 直し方はお任せしますが、**ありふれた社名を落とさない形にしてください。**

**この類の素材が、計測に 1 件もありません。** `exact` へ上の 8 件を足してください。
