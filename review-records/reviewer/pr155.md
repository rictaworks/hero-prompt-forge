## 3. 指摘

### 3-1. 【要修正】環境主導の案が、最上位の指定（コピースペース）を打ち消しかねません

- 場所：`src/backend/config/variation_rules.yml`（`environment_led.focus`）
- 内容：`the surrounding space filling the frame with the subject small within it`
- 基準：DP（Fail Fast・関心の分離）／`requirements.md` 4.1 の 5「優先順位 ①コピースペース確保」・4.2「すべての案にコピースペースの指定を含める」

`CopySpace` は `clear copy space across the left third of the frame` を足します（`copy_space_rules.yml`）。処理の順は 4（コピースペース）→ 8（バリエーション）ですので、**あとから来る展開の段が `filling the frame` を足す形**になります。生成モデルへ渡ったとき、最上位の指定を後ろの指示が上書きする読み方ができます。

`variation_rules.yml` の冒頭には「**コピースペースの指定を打ち消す指示を書きません**」と書いてありますが、`variation_rules.rb` の `ensure_text!` が見ているのは「英文かどうか」と「打ち消しの言い回しかどうか」の 2 点だけで、**この約束を検める仕組みがありません**。人が編集するデータですので、約束を文章で置くだけでは守られません。

対応の案は 2 つです。

1. `focus` の言い回しを、余白と両立する形へ直します（例：`the surrounding space dominating the composition with the subject small within it`）。
2. `variation_rules.rb` に、`CopySpace::RESERVED_MARK` と衝突する語（`filling the frame` 等）を止める検めを足します。

### 3-2. 【要修正】抽象背景の案に、被写体を前提とする指示が残ります

- 場所：`src/backend/app/services/generation/variation_expander.rb:96`（`dropped_notes` ／ `person_safety_replacements`）
- 基準：DP（surprise の少ない構造）／`requirements.md` 4.1 の 5（矛盾解決）

この PR は「具体物を置かない案に『後ろ姿の被写体』を指示すると食い違う」という理由で、**人物を避ける構図だけ**を外しています。ところが同じ理由が当てはまる指示が、外されずに残ります。

- `shallow depth of field on the subject plane`（`initial.yml` の `photoreal.depth_of_field`。PR 本文の 3 案目の出力にもそのまま出ています）
- `the main subject placed at the upper right intersection of a rule of thirds grid`（`copy_space_rules.yml` の `subject`）
- `the subject contained within the right two thirds of the frame`（同 `gaze`）

つまり **「具体物を置きません」と言いながら、`the main subject` を置く場所を指示している**状態です。人物構図だけを外す判断は、この PR が掲げた理由に照らして中途半端です。

対応の案です。`keeps_people` という真偽 1 つで持たせるのではなく、「その案で外す素材の種類」を規則の側で持たせる形（例：`drops: [person_safety]` を `drops: [person_safety, subject_placement]` へ広げられる形）にすると、あとから増やせます。少なくとも `depth_of_field` の扱いは、この PR の中で決めてください。

### 3-3. 【要修正】選び直したあとも、控えが選び直す前の値のままです

- 場所：`src/backend/app/services/generation/variation_expander.rb:80`（`variation`）
- 基準：QC10（記録の正確さ）／CLAUDE.md「デバッグトレースができるように書きます」

`variation` は `main_terms` を差し替えますが、**ノートを直しません**。その結果、次の食い違いが残ります。

- 2 案目・3 案目の `style_spec_applied` ノートは `specifications: ['35mm lens', ...]` のままです。実際の `main_terms` は `24mm wide angle lens` ・ `50mm lens` です。
- 3 案目の `person_safety_applied` ノートは `compositions: ['the subject seen from behind']` のまま残ります。実際にはその素材を外しています。`person_safety_dropped` を別に足していますが、**外した記録と当てた記録が同居する**形です。

issue #51（アートディレクションノート）は、このノートをそのまま利用者へ見せる前提です（`style_spec.rb:70` のコメント）。**記録が実際のプロンプトと違うまま次の段へ渡ると、利用者へ誤った説明が出ます。**

対応の案です。案ごとに `style_spec_applied` を選び直した値で置き換える（`replace` でノートも差し替える）か、`person_safety_applied` を外した案では取り除きます。

### 3-4. 【要修正】規則辞書の版を検めていないため、素材が黙って落ちる経路があります

- 場所：`src/backend/app/services/generation/variation_expander.rb:110`（`specification_replacements`）、同 `:100`（`swapped_terms`）
- 基準：QC10（想定外を握りつぶさない）／DP（Fail Fast）／CLAUDE.md「フォールバックを禁止します」

```ruby
applied[:specifications].zip(chosen).to_h
```

`applied[:specifications]` は下書きのノート（`StyleSpec` が付けたもの）から来ます。`chosen` は **`VariationExpander` が自分で受け取った規則辞書**から作ります。**この 2 つが同じ版であることを、どこも確かめていません。**

`StyleSpec` は `ensure_same_version!`（`style_spec.rb:110`）で同じ検めを持っています。`CopySpace` も `ensure_not_reserved!` を持ちます。**展開の段だけ、この関所がありません。**

版が食い違い、`required` の項目数が減った場合、`zip` は足りない分を `nil` で埋めます。すると `swapped_terms` の

```ruby
draft.main_terms.filter_map { |term| replacements.key?(term) ? replacements[term] : term }
```

が、**その素材を何の記録も残さずに落とします**。落ちるのはレンズや照明といった撮影指示で、`requirements.md` 4.2 は「撮影指示を欠くプロンプトは出力しない」と定めています。`filter_map` の `nil` は「抽象背景で人物構図を外す」ための仕掛けですが、**同じ仕掛けが、意図しない消失の口にもなっています。**

対応の案です。`expand` の先頭で `draft.dictionary_version` と `rules.version` の一致を検め、違えば `VersionMismatchError` で止めてください。あわせて `applied[:specifications].size == chosen.size` を検め、違えばその場で失敗させてください。

## 4. 提案

### 4-1. 選び直した事実が、記録に残りません

`Trace.step('generation.variations_expanded', ...)` が残すのは `style_family` と案の数だけです（`variation_expander.rb:57`）。**どの案で何を何へ差し替えたか**が残りませんので、「2 案目のレンズが想定と違う」という問い合わせを、記録から追えません。案ごとに 1 行、差し替えた件数と外した件数を残すことをお勧めします。

### 4-2. 差し替えが空振りしても気づけません

`replacements` の鍵が `main_terms` に 1 つも無い場合（前の段が素材を落とした場合など）、差し替えは黙って何もしません。新しい値も入りません。**鍵が使われたかどうか**を検めると、この空振りに気づけます。

### 4-3. 実写系以外は、案の違いが `focus` の 1 語だけです

`initial.yml` で一覧の形を持つのは `photoreal.lens_mm` と `photoreal.person_safety` だけです。`illustration` ・ `three_d` ・ `abstract` は、すべて 1 つの文字列です。したがってこの 3 系統では、3 案の違いが `focus` の 1 語だけになります。受け入れ条件は満たしますが、「構図の異なる 3 案」としては弱い出力です。規則辞書の側で、これらの系統にも選べる値を持たせることを検討してください（この PR の外で構いません）。

なお `abstract` 系統に `abstract_background` の案を当てると、`an abstract composition of planes, gradients and light` が系統の指定とほぼ重なります。

### 4-4. `main_terms.last` に頼るテストがあります

`variation_expander_spec.rb` の「主役の置き方が案ごとに違います」は `draft.main_terms.last` を `focus` と見なしています。`Draft#add` は `uniq` を掛けますので、`focus` と同じ文字列がすでにあると並びが変わり、この前提が崩れます。印（`variation` ノートの `composition`）から引く形が安全です。

### 4-5. 設定を読み込むクラスが 4 つ目です

`CopySpaceRules` ・ `WordForms` ・ `RomajiTable` ・ `VariationRules` が、それぞれ「YAML を読む → 検める → 凍らせる → 覚える」を書いています。`deep_freeze` も `Draft#deep_copy_freeze` と別に書かれています。DP の DRY に照らし、共通の土台へまとめる余地があります（この PR の外で構いません）。

### 4-6. テストの置き場です

CLAUDE.md のディレクトリ表は、PR ごとのテストを `test/pr<番号>/` に置くと定めています。この PR は `src/backend/spec/` に置いています。既存の運用を踏襲した形ですので、この PR で直す必要はありませんが、**どちらが正なのかを CLAUDE.md の側で決めてください。**
