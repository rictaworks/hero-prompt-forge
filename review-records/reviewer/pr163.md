## 3. 指摘

### 3-1. 【要修正】入力が Hash でない場合に、項目名の付かない `TypeError` になります

- 場所：`src/backend/app/services/generation/prompt_generation_service.rb:102-106`（`summary_of`）
- 基準：DP（Fail Fast ・ 想定外を黙って通さない）／ QC10 ／ コーディング規約「フォールバックを禁止します」

`summary_of` は `raw.respond_to?(:[])` で受け取れる形かどうかを見ます。これは **issue #133 ・ #129 で退けられた見分け方**です。`InputNormalizer#take_known`（`input_normalizer.rb:109-118`）のコメントが、そのまま同じことを書いています。

> 「鍵で引ける形か」を、形そのもので見ます。`[]` を持つかどうかで見ると、文字列・配列・数値・構造体がいずれも通り抜けます。通り抜けたあとで `raw[:industry]` を呼ぶと、項目名の無い `TypeError` や `NameError` になり、利用者へ理由を返せません（issue #133）。

この PR は、**その見分け方を、いちばん外側の入口へ持ち込み直しています。** 手元で測りました。

```
String  -> TypeError: no implicit conversion of Symbol into Integer
Array   -> TypeError: no implicit conversion of Symbol into Integer
Integer -> TypeError: no implicit conversion of Symbol into Integer
NilClass -> Generation::InputNormalizer::InvalidInputError: [{:field=>:root, :reason=>:invalid_type}]
Object   -> Generation::InputNormalizer::InvalidInputError: [{:field=>:root, :reason=>:invalid_type}]
```

正規化まで届けば項目名と理由が付きますが、**この段が先に落ちるため、項目名も理由も付きません。** この段は issue #54（非同期ジョブ）から呼ぶ入口です。

あわせて、`return nil unless raw.respond_to?(:[])` は、**`[]` を持たない値のときに禁止入力の検査を黙って飛ばします。** 結果として正規化が拾いますが、「検査を飛ばす」という分岐が記録に残りません。

対応の案です。`summary_of` の前に `raw.is_a?(Hash) || raw.is_a?(ActionController::Parameters)` を検め、外れたら `InputNormalizer` と同じ形（`{field: :root, reason: :invalid_type}`）で失敗させてください。判定を書き写さずに済むよう、`InputChoices` か `InputNormalizer` 側へ判定を出す形が読みやすいです。

### 3-2. 【要修正】`service_summary` が文字列でない場合に、項目名の付かない誤りになります

- 場所：`prompt_generation_service.rb:93-100`（`normalized`）／ `forbidden_detector.rb:99-102`
- 基準：QC10 ／ DP（関心の分離）

`service_summary: ["a"]` を渡して測りました。

```
Generation::ForbiddenDetector::InvalidInputError: 文字列を渡してください: Array
```

正規化を先に置いた場合は `InputNormalizer::InvalidInputError` の `{field: :service_summary, reason: :invalid_type}` になり、上位の層が項目名から文言を組み立てられます。**禁止入力の検出を前へ出したことで、この 1 項目だけ、項目名の付かない別の型の誤りに変わりました。**

PR 本文と記録は「正規化を先に置くと形式の誤りとして返ります」を理由に挙げていますが、**逆向きの取りこぼしが起きています。** 権利に関わる判定より前に、`service_summary` の型と長さだけを検める（あるいは文字列でなければ検査を飛ばして正規化へ委ねる）形をご検討ください。

### 3-3. 【要修正】長さの上限より先に、上限の無い文字列を走査します

- 場所：`prompt_generation_service.rb:93-100`（`normalized`）
- 基準：OWASP10（資源の消費）

`MAX_SERVICE_SUMMARY_LENGTH` は 1,000 文字です（`input_choices.rb:25`）。ところが**検出は正規化より先に走りますので、上限を超えた文字列がそのまま正規表現に掛かります。** 手元で測りました。

| 文字数 | 検出に掛かった時間 |
|---|---|
| 9,999 | 0.006 秒 |
| 99,990 | 0.061 秒 |
| 999,999 | 0.582 秒 |
| 3,999,996 | 2.28 秒 |

線形ですので破局的な後戻り（ReDoS）はありません。当たりやすい形（`他社の…` の繰り返し 24 万文字）でも 0.204 秒でした。**危険なのは後戻りではなく、上限の素通りです。** 上限の 4,000 倍の入力で 2.28 秒の計算を、申し込みごとに引き受けます。

対応の案です。禁止入力の検出の前に、`service_summary` の長さだけを先に検めてください。**権利の判定を後ろへ戻す必要はありません。** 長さは形式の誤りですので、順序の意図（権利の理由を先に返す）とは競合しません。

## 4. 提案

- **【提案】案の印が見つからなくても、黙って通ります。** `:139-141`（`variation_of`）は `find` の結果をそのまま返しますので、控えが無ければ `nil` が `Package#variation` に入り、`to_h` にも `variation: nil` として出ます。展開の段が必ず付けますので今は起きませんが、**フォールバックを禁じる決まりに照らすと、`nil` はその場で失敗させる形が揃います。**
- **【提案】`VersionMismatchError` を通す赤テストがありません。** 定義した 4 つの例外のうち、`ForbiddenInputError` ・ `MissingCopySpaceError` ・ `MissingDictionaryError` には対応するテストがあります。この 1 つだけ、通る道が固定されていません。
- **【提案】どの案で落ちたかが記録から分かりません。** `packaged` は案ごとに呼ばれますが、`Trace.step` で包まれていません。3 案のうち 2 案目で `MissingCopySpaceError` が出ても、外側の 1 行にしか残りません。案の番号（または `composition`）を添えた `Trace.step` を 1 段足すと追えます。
- **【提案】`Adapters::ModelAdapter`（`:134`）は `::Adapters::ModelAdapter` と書くと、解決の経路が 1 通りに決まります。** いまは `Generation::Adapters` を探してから最上位へ落ちる形です。動いていますが、`Generation::Adapters` を将来足したときに黙って行き先が変わります。
- **【提案】固有名詞の「読みが分からない」控えが、利用者へ出ません。** `AdjustmentList#line_for`（`adjustment_list.rb:32-41`）は `ProperNoun::NOTE_KIND` を扱いません。`proper_noun.rb:12-14` は「アートディレクションノート（issue #51）が、利用者へ読みの追記を促せます」と書いていますが、**この PR で固有名詞の段が実際に通るようになったことで、その未実装が表に出ます。** 日本語のまま生成 AI へ渡る素材ができるのに、利用者に知らせる手立てがありません。issue #51 の側の課題ですので、**申し送りへ 1 行足してください。**

## 2. 「止める」という判断の妥当性

**妥当です。** 次の理由で、そのまま進めてよいと考えます。

1. **`requirements.md` 4.2 が、そのとおりに書いています。** 「実写系プロンプトには撮影指示（レンズ・照明・被写界深度）を必ず含める。**撮影指示を欠くプロンプトは出力しない。**」黙って欠けたまま出す作りは、この一文に正面から反します。
2. **4.2 の「出力を停止せず統合した案を返す」とは、ぶつかりません。** その一文は「**矛盾する入力**を受けた場合」を指します。今回止まるのは、利用者の入力ではなく**規則辞書どうしの食い違い**です。利用者に弱められる筋合いのものではありません。
3. **弱める余地がありません。** 4.1 の 5 の優先順位は「①コピースペース ＞ ②ブランドカラー ＞ ③スタイル系統 ＞ ④トーン装飾」です。撮影の指示は③に当たり、**「弱めて残す」対象はその下位（④）です。** 上位を弱めて残す道が、そもそも定めにありません。
4. **既定の規則辞書では起こりません。** 起こるのは、運用の方が撮影の指示に当たる語を「排除する語」として登録した場合だけです。**設定の誤りに気づける形になっているほうが、静かに品質が落ちるより安全です。**
5. **コピースペースと扱いがそろいます。** 同じ理由で落ちる 2 つの素材に、同じ形の関所を置いたことで、読む人が迷いません。
