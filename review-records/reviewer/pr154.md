## 要修正

### 要修正 1：パラメータを本文へ連結する形が示されていません（issue #45、#46）

`src/backend/app/services/adapters/midjourney_adapter.rb` 34 行目からの `parameters_for` は `{'--ar' => '16:9', '--no' => '...'}` を返しますが、**これを本文の末尾へどう連結するかを、この層は示していません。**

- Midjourney はパラメータを**本文の最後**へ置く必要があります。連結の責任が呼び出し側に残り、順序を誤ると効きません。
- 鍵の形がアダプタごとに違います（`'--ar'`／`'size'`（`dalle_adapter.rb` 43 行目）／`'aspect_ratio'`（`stable_diffusion_adapter.rb` 44 行目、`nano_banana_adapter.rb` 41 行目））。**同じ `Formatted` を受け取っても、一様に組み立てられません。**
- Midjourney 系では、同じ打ち消しが `negative_prompt` と `parameters['--no']` の**両方**に入ります。素直に連結する呼び出し側は二重に出します。

`Formatted` に「そのモデルへ貼り付けられる最終文字列」を返す方法（例：`#to_prompt`）を持たせ、連結の形をアダプタ側で決めきってください。DP の「実装よりインターフェースに依存する」「surprise の少ない構造」に照らした指摘です。

### 要修正 2：打ち消しが 0 件のとき、値の無い `--no` を出します（issue #46）

`midjourney_adapter.rb` 39 行目は、`draft.negative_terms` が空でも `NEGATIVE_PARAMETER` の鍵を必ず作ります。結果は `--no` の値が空文字です。**Midjourney は値の無い `--no` を受け付けません。**

`Generation::Draft` の `negative_terms` は既定値が空配列ですので、アンチAIルック規則が 1 件も当たらない下書きで実際に起こります。空なら鍵ごと落としてください。あわせて、`stable_diffusion` ／ `nano_banana` で `negative_prompt` が空文字なのに `Formatted#negative?` が `true` を返す点も、`model_adapter.rb` 32 行目の「欄を持つモデルだけが値を持ちます」という約束と食い違います。

### 要修正 3：DALL-E 系・nano banana 系の本文が、自然文になっていません（issue #47、#49）

`dalle_adapter.rb` 29 行目からの `main_prompt_for` は、素材の先頭 1 文字を大文字にして句点で並べるだけです。実測の出力は次のとおりです。

```
A hero image for a website, composed for a 16:9 frame. A calm office. 35mm lens. The main subject placed at the upper right intersection of a rule of thirds grid. ... Composed for a 16:9 wide crop.
```

- 「A calm office.」「35mm lens.」「The main subject placed at ...」は、いずれも**述語を持たない名詞句**です。句点を打っても文になりません。**カンマ区切りの語並べを、区切り文字だけ句点へ替えた形です。** DALL-E 系が自然文を求める理由（要素どうしの関係を伝えること）を満たしていません。
- **アスペクト比を二度言います。** 冒頭の `composed for a 16:9 frame` に加えて、`config/copy_space_rules.yml` 由来の `composed for a 16:9 wide crop` が末尾に来ます。同じことを違う言い方で二度指示しています。
- `nano_banana_adapter.rb` 31 行目も同じ作りで、同じ二重指示が起きます。

素材を主語・述語のある文へ組み立てる（例：`The frame reserves clear copy space across the left third.`）か、素材の側に文としての形を持たせる設計へ寄せてください。あわせて、アスペクト比の指示が素材に既に入っている場合は重ねないでください。

### 要修正 4：重み付けが、括弧とコロンを含む素材を壊します（issue #48）

`stable_diffusion_adapter.rb` 31 行目の `weighted` は、素材をそのまま `(` と `)` で包みます。素材に括弧やコロンが含まれると、実測のとおり `(clear copy space (left third) for a headline: large:1.2)` になります。**Stable Diffusion 系の記法では、入れ子の括弧は別の強調として、コロンは別の重み指定として解釈されます。** 意図しない強さになります。

規則辞書は管理画面から人が編集するデータですので、括弧やコロンの混入は起こり得ます。包む前に `(` `)` `:` を `\` で退避させるか、混入した素材をその場で失敗させてください（フォールバック禁止の観点では、後者が本プロジェクトの流儀に合います）。

### 要修正 5：重みを当てる対象を、英語の部分一致で決めています（issue #48）

`stable_diffusion_adapter.rb` 25 行目の `EMPHASIS_MARK = 'copy space'` は 2 つの問題を持ちます。

- **黙って重みが消えます。** 実測のとおり、言い回しが `clear negative space for a headline ...` に変わると、重みが 1 件も付かないまま、例外もノートも残さず通ります。requirements.md 4.1 の 5 が最上位に置く指示の強調が、静かに失われます。CLAUDE.md の「想定外は握りつぶさず失敗させます」に反します。
- **同じ知識が二重に置かれています。** 同一の文字列は `src/backend/app/services/generation/copy_space.rb` 44 行目に `CopySpace::RESERVED_MARK` として既にあります（DP の DRY）。

素材へ役割の印を持たせて構造で選ぶか、少なくとも既存の定数を参照し、**当たらなかった場合に失敗させるかノートへ残してください。**

### 要修正 6：nano banana 系が「打ち消しの欄を持つ」前提になっています（issue #49）

`nano_banana_adapter.rb` 21 行目は `negative_prompt?` に `true` を返します。**実在のモデルの記法と食い違います。**

- nano banana（Gemini 系の画像生成モデル）は会話文で指示する作りで、**打ち消しを渡す専用の欄を API に持ちません。**
- 同系統の Imagen でも、負の指定を渡す項目は新しい版で廃止され、**「出したいものを肯定形で書く」ことが公式の案内です。**

このまま進めると、`negative_prompt` を受け取った呼び出し側が、行き場の無い打ち消しを本文へ書き込みかねません。**それは、この PR が DALL-E 系について正しく避けた失敗そのものです。**

**打ち消しの欄を持たない扱い（`false` ＋ `nil`）へ寄せるか、根拠となる仕様の所在を Issue かコメントへ明示してください。** あわせて、`parameters` の `'aspect_ratio'` についても、どの呼び出し方の項目名なのかを明示してください。DALL-E 系の `{'size' => '16:9'}`（`dalle_adapter.rb` 43 行目）も同じで、**画像生成の呼び出しが受け付ける `size` は `1792x1024` のような画素の指定です。`16:9` をそのまま渡すと弾かれます。** 推奨パラメータとして `prompt_outputs.parameters` に保存され、利用者の目に触れる値ですので、そのまま使える形にしてください。

## 提案

### 提案 1：プロンプトへ入る英文を、設定ファイルへ分離してください

`dalle_adapter.rb` 20 行目の `OPENING = 'A hero image for a website'`、`nano_banana_adapter.rb` 18 行目の `'A website hero image'`、および `", composed for a #{aspect_ratio} frame"` は、**そのまま生成モデルへ渡る英文**です。

本プロジェクトは同種の英文を `config/copy_space_rules.yml` ／ `config/word_forms.yml` ／ `config/rule_dictionary/initial.yml` へ出す作りで統一しており、`Generation::CopySpaceRules` は「実装の中に埋め込みません」と明記しています。requirements.md 8 も、モデル各社の仕様変更への追随を求めています。**同じ扱いへ寄せてください。** 重み `'1.2'` も、モデルの版で見直す値ですので同様です。

ハードコードの検査は日本語のみを対象にしているため CI では捉えられません。検査の対象を広げるかどうかは、別の Issue で扱うのが妥当です。

### 提案 2：処理の経過を残してください

同じ工程の `Generation::CopySpace` ／ `StyleSpec` ／ `RuleEngine` ／ `ForbiddenDetector` は、いずれも `Trace.step` で経過を残しています。**アダプタ 5 本は 1 か所も残していません。** どのモデルの記法で、素材を何件、打ち消しを何件、重みを何件当てたのかが追えません。CLAUDE.md の「デバッグトレースができるように書きます」に照らした指摘です。

### 提案 3：`NotImplementedError` と `format` の名前を見直してください

- `model_adapter.rb` 26 行目で `NotImplementedError` を `StandardError` の子として定義しています。**Ruby が持つ同名の例外（`ScriptError` の子）を、`Adapters` 名前空間の中で覆い隠します。** `AdapterNotImplementedError` のような名前を推奨します。
- 公開メソッド名の `format` は `Kernel#format` を覆います。requirements.md のクラス図に沿った命名ではありますが、アダプタの中で書式整形が必要になったときに混乱します。

### 提案 4：例外文に利用者由来の値をそのまま入れています

`model_adapter.rb` 60 行目の `target_model.inspect` と 119 行目の `value.inspect` は、利用者の入力に由来し得る値です。記録には「利用者の入力を含みません」とありますが、実際には含みます。**入力の正規化を通らずにこの層へ届いた場合、記録へそのまま流れます。** 値そのものではなく、鍵の名前と型に留める形を推奨します。

## 申し送り

- テストを `src/backend/spec/` に置いています。CLAUDE.md は `test/pr<番号>/` を定めますが、既存の RSpec がすべて `src/backend/spec/` にあり、CI もそこを走らせています。**既定路線に沿った配置と判断し、指摘としません。** 置き場の扱いは、規約の側を実態へ合わせるかどうかを別途決めてください。

## 要修正

### 要修正 1：自然文が、実際の経路では文として成立していません（issue #47、#49）

`src/backend/config/model_adapters.yml` 43 行目の `body: "The image includes %<terms>s"` に、素材をそのまま並べています（`narrative_adapter.rb` 50 行目）。実測の文には、英語として 3 つの問題があります。

**（1）`includes` が動詞として受けられない句を並べます。**

```
The image includes ... , and composed for a 16:9 wide crop.
```

`include` は目的語に名詞句を取ります。`composed for a 16:9 wide crop` は過去分詞句で、名詞句ではありません。**`The image includes composed for ...` は文になりません。** `config/copy_space_rules.yml` 55 行目からのアスペクト比の言い回しは 3 種類とも `composed for ...` で始まりますので、**16:9 ・ 21:9 ・ 3:2 のどれを選んでも必ずこうなります。**

**（2）冠詞が落ちます。**

```
The image includes a calm office, 35mm lens, ...
```

`35mm lens` は可算名詞で、`a 35mm lens` が要ります。また、レンズは画に写るものではなく撮影の手段ですので、`includes` の目的語として意味が通りません。`shot on a 35mm lens` のような別の述語が要ります。**素材の英文は「1 件 1 指示の断片」として作られており、`includes` の目的語になる前提で書かれていません。**

**（3）関係が伝わりません。** 1 回目に「自然文を求めるモデルが期待しているのは、要素どうしの関係が伝わる形です」と書きました。実測の文は、**カンマ区切りの並びを 1 つの `includes` の中へ入れ直したもの**で、被写体・撮影・構図・余白・抑制の関係は、並べる前と同じく表れていません。DALL-E 系へ渡す価値が出ていません。

**根治は、1 回目の要修正 5 で挙げた「素材へ役割の印を持たせて構造で選ぶ」と同じ道です。** 役割ごとに述語の型を持たせ、2 文から 4 文へ分けてください。例を挙げます。

```
The scene shows a calm office, photographed on a 35mm lens.
The main subject sits at the upper right intersection of a rule of thirds grid and stays within the right two thirds of the frame.
The left third is kept clear as copy space and rendered as an even low contrast surface.
The whole frame is composed as a 16:9 wide crop.
```

**テストが素通りさせている理由も併記します。** `spec/services/adapters/model_adapter_spec.rb` 6 行目からの `main_terms` は 3 件で、`composed for ...` を含みません。244 行目の「素材が既にアスペクト比を述べていれば、重ねません」だけが `composed for a 16:9 wide crop` を足しますが、**判定は `prompt.scan('16:9').size` が 1 であることだけ**で、文の成立を見ていません。TM の観点で、**代表の素材を実際の経路（`CopySpace#apply` の出力）から取ってください。**

### 要修正 3：記法で意味を持つ文字の検査が、重み付けの対象にしか掛かっていません（issue #48）

`stable_diffusion_adapter.rb` 50 行目からの `weighted` は、`EMPHASIS_MARK` を含む素材のときだけ `ensure_weightable!` を呼びます。**それ以外の素材は検査せず、そのまま本文へ入ります。** 実測です。

```

```

`(soft light)` は、Stable Diffusion 系（A1111 系記法）では**丸括弧そのものが約 1.1 倍の強調**です。重み付けを「最上位の指示にだけ付ける」という、この PR の中心の判断が、**素材に括弧が 1 つ混ざるだけで崩れます。** 例外もノートも残りません。要修正 4 として挙げたのと同じ壊れ方が、対象を変えて残っています。

同じ形の問題が Midjourney 系にもあります。`midjourney_adapter.rb` 37 行目は素材を検査せずカンマで連結しますので、素材に `--` が混ざると本文の途中にパラメータが現れます。

**Midjourney はパラメータを本文の途中に置けません。** 本文へ入る素材が、そのモデルの記法で意味を持つ文字を含まないことを、**系統ごとに検めてください。**

### 要修正 4：DALL-E 系の `size` が、21:9 ・ 3:2 で黙って別の比になります（issue #47）

`1792x1024` そのものは、**DALL-E 3 の画像生成が受け付ける 3 つの大きさの 1 つです。** ご依頼の「実際の呼び出しで通る値か」は満たしています。問題は対応表の中身です。`model_adapters.yml` 54 行目からです。

```yaml
sizes:
  "16:9": "1792x1024"   # 1792/1024 = 1.75。16:9 = 1.778。近いです
  "21:9": "1792x1024"   # 21:9 = 2.333。まったく別の比です
  "3:2":  "1792x1024"   # 3:2  = 1.5。別の比です
```

`Generation::InputChoices::ASPECT_RATIOS` は 3 件とも対応表にありますので、**正当な入力が止まることはありません**（実測で確認しました）。そのかわり、**21:9 ・ 3:2 を選んだ利用者へ返る `parameters` が、自己矛盾します。**

```
[dalle 3:2] params={"aspect_ratio"=>"3:2", "size"=>"1792x1024"}
            本文 : ... and composed for a 3:2 wide crop.
```

同じ連想配列の中で `aspect_ratio` が `3:2`、`size` が `7:4` を指し、本文はさらに `3:2` と述べます。**受け取った利用者は、どれに従えばよいか決められません。** `dalle_adapter.rb` 17 行目のコメントは「横長のうち最も近いもの」と述べますが、**近いのは 16:9 だけです。**

これは CLAUDE.md が禁じるフォールバック（黙って別の値へ寄せる）に当たります。次のいずれかにしてください。

- 対応表に無い比を失敗させているのと同じく、**その比を実現できない場合も失敗させる**
- または、**すり替えた事実をアートディレクションノートへ残し、画面に出す**

あわせて、**この対応表がどの呼び出しのものかを、ファイルへ明記してください。** 新しい画像生成の呼び出し（`gpt-image-1`）が受け付ける横長は `1536x1024` で、`1792x1024` は弾かれます。requirements.md 8 が各社の仕様変更への追随を求めていますので、**対象の版が書かれていないと、どちらへ追随すべきかが判断できません。**
