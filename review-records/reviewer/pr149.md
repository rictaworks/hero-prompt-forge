### 5. 促音で終わるかなで `NoMethodError` が出ます

- 該当：`src/backend/app/services/generation/romaji.rb:109-114`（`doubled_consonant`）と `:96-104`（`single_at`）
- 基準：QC10 ／ CLAUDE.md（フォールバック禁止・例外処理・デバッグトレース） ／ DP（Fail Fast）

注釈は「促音は、次の音の子音を重ねます。**次が無ければ落とします。**」と書いていますが、落ちません。末尾の「っ」では `kana[index, 2]` が `nil` を返し、`single_at` の `letter.match?(/\s/)` が `nil` に対して呼ばれます。

```
Romaji.of('あっ')
  => NoMethodError: undefined method `match?' for nil

ProperNoun#call('お客さまの「あっ」という驚きをお届けします。')
  => NoMethodError（同上）
ProperNoun#call('「がんばるっ」が合言葉です。')
  => NoMethodError（同上）
```

**利用者の文章が原因で、種別の無い `NoMethodError` が上がります。** この設計は「想定外は握りつぶさず失敗させる」方針ですので落ちること自体は構いませんが、**落ち方が定義された例外でないため、上位で扱い分けられず、記録にも意味が残りません。** `NotKanaError` などの定義済みの例外へ寄せるか、注釈どおり空文字を返すかの、どちらかへ揃えてください。

### 6. ヘボン式として不自然な出力があります

- 該当：`src/backend/config/kana_romanization.yml`（`ん: "n"`・拗音の表）と `romaji.rb:109-114`
- 基準：QC10 ／ Issue #44（ローマ字表記）

| 種別 | 入力 | この実装 | ヘボン式 | 所見 |

## 提案

1. **長音の扱いに表記ゆれが出ます。** 「ゆうき」は `Yuuki`、「ユーキ」は `Yuki` です。「とうきょう」は `Toukyou`、「トーキョー」は `Tokyo` です。同じ音の名前が、書き方で別の綴りになります。長音記号を落とす判断自体は文書化されていますので、**かなの長音（おう・うう）の扱いと揃えるかどうか**を、issue として残すことをお勧めします。
2. **`KEPT_AS_WRITTEN`（`proper_noun.rb:35`）だけがコード側に残っています。** `gloss` は設定へ出しているのに、同じくプロンプトへ入る英文がコードにあります。ハードコードの検査は日本語だけを見ますので通りますが、**同じ性質の文字列を 2 か所へ置くのは DP（DRY・一貫性）から外れます。** 設定側へ寄せてください。
3. **`ProperNoun.new` のたびに YAML を 2 回読みます。**（`proper_noun.rb:68-75` の `load_rules` と `load_suffix_readings` が、それぞれ `read` を呼びます。）`Romaji` は記憶していますので、`ProperNoun` も揃えられます。
4. **`draft.input` が Hash でないとき、黙って素通りします。**（`proper_noun.rb:94`）実測で、`input` に文字列を入れた下書きが、何事も無かったように返りました。`style_spec.rb:104` に同じ書き方があり、この PR の新規ではありませんので提案に留めますが、**フォールバック禁止の方針からは、種別の誤りとして失敗させる形が筋です。**
5. **種別が規則の並び順で変わります。** 「さくら堂」は、かぎ括弧の中では `a proper name`、地の文では `a shop name` になります。動作としては妥当ですが、**設定の並べ替えで結果が変わる**ことを設定側の注釈へ書き添えてください。
6. **半角英数字だけの語にも「日本語のまま残しました」と添えます。** 「「abc」」が `abc, a proper name kept as written in Japanese` になります。文言が事実と食い違います。
7. **セキュリティレビューの記録（`review-records/security-review/feature-issue-44-proper-noun.md`）の記述を、実測に合わせて直してください。** 「取りこぼしは、利用者の指定を壊しません」「正規表現の危険：入れ子の量指定子がありません（目視）」とありますが、**壊す経路（要修正 1・2）が実在します。** 目視の範囲が「入れ子の量指定子」に寄っており、**欲張りな量指定子が誤って広く一致する**という、この規則の実際の弱点を捉えられていません。
8. **PR 本文の「判断したこと」も同様です。** 「取りこぼしても、お客さまの指定を壊しません」という記述は、いまの実装では成り立ちません。pr-checker へ回す前に直していただくのが確実です。
