## 要修正（呼び出し側へつなぐ前）

### 3. 人物の有無を判定しないまま、人物の構図を 3 件とも足します

- 該当：`src/backend/app/services/generation/style_spec.rb:51-72`
- 基準：requirements.md 4.1 の 3 ／ 4.1 の 5 ／ DP（一貫性）

requirements.md 4.1 の 3 は「**人物を含む場合は**顔・手指の破綻リスクを構図で回避する」と条件付きで定めています。実装は、実写系であれば無条件に足します。初期データで実測した実写系の出力です。

```
35mm lens / soft key light ... / bounced fill ... / subtle rim light ... / shallow depth of field ...
the subject seen from behind
hands cropped out of the frame
a distant figure within the scene
```

問題が 2 つあります。

- **人物のいないヒーローに人物を呼び込みます。** 料理・製品・工場・不動産の外観はいずれも実写系ですが、そこへ「後ろ姿の被写体」「遠景の人物」が指示として入ります。
- **3 件が互いに矛盾します。** 後ろ姿・手元だけ・遠景を同時に指示すると、生成モデルはどれを採るか決められません。4.1 の 5 は矛盾の解決を求めています。

**方針が揃っていない点も申し添えます。** レンズは「選べる値の先頭を既定に使う」としているのに（`style_rules.rb:21-24`）、避ける構図だけは全件を足しています。同じ規則辞書の一覧で扱いが分かれています。

入力表（4.1）に「人物を含むか」の項目が無いため、**この判定の設計そのものが未決**です。Issue を起票して、判定の根拠（サービス概要からの推定か、入力項目の追加か）を決めてください。

### 4. 実写系で回避の構図が消えても、止まりません

- 該当：`src/backend/app/services/generation/style_rules.rb:57-59`
- 基準：requirements.md 4.2 ／ QC10（フォールバックの禁止）

`Array(rule_for(style_family)[PERSON_SAFETY_KEY])` は、鍵が無ければ空の一覧を返し、そのまま通ります。規則辞書は管理画面から人が編集するデータです（4.3）。**編集で `person_safety` を消すと、顔の回避が黙って効かなくなります。**

4.2 は「撮影指示を欠くプロンプトは出力しない」と「顔を正面から大きく描く構図は既定で回避する」を**同格で**定めています。前者は欠けたら止まるのに、**後者は黙って消えます。** 扱いが揃っていません。実写系については必須として検めてください。テストにも、実写系で `person_safety` が欠けた場合の例がありません。
