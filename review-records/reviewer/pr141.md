## 指摘

### 要修正 1：足し忘れを知らせない種類の検証があります

`spec/config/validation_messages_spec.rb:24` の `else []` です。対応表に無い種類の検証を足すと、鍵が 1 つも求まらず、テストは緑のまま通ります。**issue #124 の症状そのものが再発しても気づけません。**

実際に確かめました。

- 対応表にある種類（`length: { minimum: }`）を足す → `[:too_short]` で赤くなります。網は働いています。
- 対応表に無い種類（`acceptance: true`）を足す → **8 例すべて緑のままです。** そのうえで `User#save!` を呼ぶと `I18n::MissingTranslationData` になります。

CLAUDE.md の「フォールバックを禁止します。想定外は握りつぶさず失敗させます」にも反します。`else` で `[]` を返さず、その場で失敗させてください。

### 要修正 2：使っていない公開面と、事実と違うコメントがあります

`input_normalizer.rb:19` の `include InputChoices` です。`InputNormalizer` の公開面へ 15 個の定数が黙って生え、同じ定数に 2 通りの参照経路ができています。DP の YAGNI と「surprise の少ない構造」に反します。

### 提案 1：不正な UTF-8 で素の例外になります

`input_normalizer.rb:128` の `value.strip` と `brand_colors.rb:31` の同じ行で、`Encoding::CompatibilityError` が出ます。項目名も理由も付かず、**issue #133 が直した症状と同じ形です。**

### 提案 2：空の要素を落とす理由が、決まりの持ち主から離れています

理由が spec にあり、決まりを持つ `brand_colors.rb` のクラスコメントに書かれていません。

### 提案 3：注釈の位置がずれています

同時呼び出しに関する注釈が、別の節の直前に付いています。

### 提案 4：ですます調の確認が二重です

`locales_spec.rb` が `ja` 配下すべてを同じ条件で確かめています。
